# ORG — Organization, governance and contribution policy

**Scope.** These requirements cover the project-level structure of FerroAstro. They include the mission document, the flagship Mercury perihelion ladder (the parent of every rung requirement), the requirements and traceability system itself, architecture decision records, milestones and labels, the software classification and tailoring statement, contributor sign-off, and human oversight of agent-authored work. Source: Journal #5 (`docs/strategy/journal/05-organization-standards.md`), revised by Journal #6 (`06-maintainer-decisions.md`). Journal #6 changes three things here. ORG-008 now requires a DCO sign-off instead of a CLA. The CLA moves to a new requirement, ORG-010. Traceability starts with `tools/trace.py`, and an ADR will evaluate StrictDoc and OpenFastTrace.

### ORG-002 — Flagship Mercury perihelion ladder

```yaml
id: ORG-002
title: "Flagship: Mercury perihelion precession ladder, each rung with a cited value and tolerance"
status: draft
criticality: high
verification: test
statement: >-
  The flagship SHALL be the Mercury perihelion precession ladder. Newtonian
  rungs: two-body (zero precession), then planets, then Moon/asteroids, then
  solar J2, then DE440-equivalent physics. Relativistic rungs: SR in two
  formulations with caveats, then the Schwarzschild test particle, then 1PN
  Sun-only, then full EIH N-body with PPN β, γ free. Each rung SHALL have an
  acceptance test with a cited reference value and a stated tolerance. Each
  rung SHALL both reproduce the published value and carry an independent
  error budget, with a numerical secular fit checked against the analytic
  formula where one exists.
acceptance: >-
  Every rung has at least one PHY- child requirement with a cited value and
  tolerance, and each such child is verified by a test (TRACE.md shows no
  uncovered PHY- requirement).
source: >-
  docs/strategy/journal/00-kickoff.md Decisions;
  docs/strategy/journal/05-organization-standards.md ORG-002 and lead review
  notes (rung expansion; answer to open question 6 = both).
parent: null
related: [ORG-001, ORG-006]
notes: >-
  Journal #5's ORG-002 text lists only four rungs (two-body, planetary, 1PN GR,
  ephemeris comparison). Its lead review says the roadmap expands them to the
  kickoff ladder, which is used here. DE440 reproduction is a separate
  milestone; fitting to observations is a later stage (kickoff).
```

### ORG-004 — Traceability is enforced and generated

```yaml
id: ORG-004
title: "Every approved test-verified requirement is cited by ≥ 1 test; TRACE.md is generated"
status: draft
criticality: medium
verification: test
statement: >-
  Every approved requirement with verification: test SHALL be cited by at
  least one test, and every ID cited by a test SHALL exist. TRACE.md SHALL be
  generated by tools/trace.py and never hand-edited.
acceptance: >-
  CI (`uv run tools/trace.py --check`) fails when an approved test-verified
  requirement has zero citing tests, when a test cites an unknown ID, or when
  the committed TRACE.md differs from the generated one.
source: >-
  docs/strategy/journal/05-organization-standards.md §2.2 and ORG-004;
  docs/strategy/journal/06-maintainer-decisions.md.
parent: ORG-003
related: [AGT-001]
notes: >-
  Journal #6: start with tools/trace.py (to be built in M0, ~150 lines per
  Journal #5) and write ADR-0010 (docs/adr/0010-requirements-tooling.md) evaluating StrictDoc
  and OpenFastTrace, revisited at M2. Their fit is UNVERIFIED. Test citation
  syntax is `/// Verifies: <ID>` (Rust) and `# Verifies: <ID>` (Python);
  Journal #5's TL;DR form `// REQ: <ID>` is superseded.
  ADOPTED WITH CONDITIONS 2026-10-20 (judge ruling on PR #19; ADR-0010):
  allow trace.py to accept named CI-gate evidence in place of a citing test
  for requirements that a CI gate enforces. Evidence (WP6 requirement gap
  table and every progress review since, m3-newtonian-nbody): STD-001…011,
  TST-001, DEP-001/002/003 and ORG-008 have no citing test because fmt,
  clippy, deny, MSRV and DCO jobs enforce them; DEP-006 is enforced by the
  wasm32 job and is uncited too (progress review after WP18). Conditions:
  (1) gate evidence counts only for the tool-verdict requirements STD-001…011,
  TST-001, DEP-001/002/003/006 and ORG-008, and never for PHY/NUM/REF/API;
  (2) a human-owned `verified_by_gate: workflow/job[/step]` field, and
  trace.py --check fails if the target is missing; (3) crit:high counts only
  once the gate is a required check pinned to the default branch (#12),
  shown as "gate (unpinned)" until then and not counted toward moving past
  draft; (4) TRACE.md lists gate evidence separately from test evidence.
```
